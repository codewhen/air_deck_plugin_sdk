## Your first result

You will create a plugin named **Hello AirDeck** with one button, **Say hello**. Its action prints `Hello from AirDeck!` to stderr, which is the diagnostic output stream. AirDeck's protocol stays on stdout.

The starter needs no broker permissions. Once this works, you can replace the hello action with your own logic or add a [typed core capability call](../reference/capabilities).

## Commands and working directory

Commands run from the root of the cloned SDK unless the page explicitly says otherwise. That root contains `deck-plugins`, `capabilities`, `docs` and `tools`.

On macOS use `python3`. On Windows, use `python` if that is how your Python installation is exposed on PATH. The documentation writes `python3` to keep commands consistent.

The new starter projects are generated in `deck-plugins/plugins/<project-name>`. They live there so the included build tooling can use the local SDK without downloading an unreleased module version. You can move a production project into your own repository later; see [project structure and SDK dependencies](../reference/project-structure).
